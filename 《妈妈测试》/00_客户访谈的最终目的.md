> 创业整个大流程：找点子 -> 验证点子是否可行 -> xxx
>
> 找点子可以通过用户访谈这种方式，但还有很多其它方式（比如根据团队现有资源、能力、经验，又或者网上浏览发现一些人的吐槽），当我们通过用户访谈这种方式找点子的时候，一般会同时验证点子，换句话说我们肯定是找到那些已经验证可行的点子
>
> 验证点子是否可行也可以通过用户访谈这种方式，有没有其它方式暂时还不知道
>
> 总的来说：用户访谈的最终目的是发现创业点子或验证创业点子是否可行
>
> 发现创业点子：还不清楚应该做什么，希望从客户身上发现问题和机会。
>
> 验证创业点子是否可行：已经有了创业想法，需要判断问题是否真实、是否值得解决。
>
> 推动创业进展：  

> ### 还没有创业点子，也可以做用户访谈
>
> > 你隐约察觉到一个机会，却想弄清楚它究竟是什么。
>
> 这正是探索性用户访谈的典型场景。
>
> 比如：
>
> 你发现近年来很多小企业都在尝试数字化管理，但你不知道具体机会在哪里。
>
> 你可以访谈这些企业，了解：
>
> - 他们有哪些工作流程？
>
> - 哪些工作最耗费时间？
>
> - 哪些问题长期没有得到解决？
>
> - 他们目前如何处理？
>
> 经过一系列交流，你可能发现一个具体的创业机会。
>
> 所以，用户访谈并不是必须从创业点子开始。
>
> 有时候，用户访谈本身就是产生创业点子的起点。

> ### 已经有点子，但不确定是否值得投入
>
> > 你迷上了一个新的商业点子，想在辞职前弄清楚它究竟站不站得住脚。
>
> 这是典型的创业假设验证。
>
> 例如，你想开发一个 AI 财务助手。
>
> 你需要弄清楚：
>
> - 财务人员真的存在你认为的问题吗？
>
> - 这个问题严重到什么程度？
>
> - 他们目前如何解决？
>
> - 他们是否愿意为解决问题投入资源？
>
> 如果发现问题根本不存在，或者客户并不在意，你就应该重新考虑这个创业点子。
>
> 这也是《妈妈测试》非常重要的价值：帮助创业者在投入大量资源之前，尽早发现错误假设。

Q：不过在开始第二遍阅读之前，我想先问你一个问题，妈妈测试这本书一直在教我们如何做好用户访谈，但做用户访谈的目的是什么？

A：这是一个非常重要的问题。我甚至认为，在开始第二遍阅读《妈妈测试》之前，你必须先弄清楚这个问题。

因为如果你不知道用户访谈究竟是为了什么，就很容易陷入一个误区：

每天认真访谈客户，记录大量信息，学会了各种提问技巧，但最后却不知道这些信息应该用来做什么。

我先给你一个核心结论：

# 客户访谈的目的

降低创业过程中的不确定性，帮助创业者做出更正确的商业决策。

用户访谈不是为了让客户认可你的想法，而是为了了解客户真实的生活、行为和问题，判断自己应该解决什么问题、为谁解决，以及这个问题是否值得投入资源。

# 三、用户访谈不是为了验证自己已经有的产品想法

这里有一个特别重要的区别。

假设你想做一款 CRM 软件。

你可能有两种完全不同的访谈思路。

错误的访谈目标

证明我的产品想法是正确的。

访谈过程：

- 我觉得企业需要 CRM。

- 我向客户介绍 CRM 的功能。

- 我问客户喜不喜欢。

- 客户说不错。

- 我认为需求已经得到验证。

最终结果：得到了一堆支持自己想法的反馈，却没有真正验证需求。

正确的访谈目标

了解客户的真实情况，判断我的创业假设是否成立。

访谈过程：

- 企业目前如何管理客户？

- 最近一次出现管理问题是什么时候？

- 当时发生了什么？

- 他们采取了什么措施？

- 这些措施耗费了多少资源？

- 为什么现有方案没有解决问题？

最终结果：获得真实信息，判断是否值得继续投入。

两种方式最大的区别在于：

第一种是希望客户认可自己的想法。

第二种是希望通过客户的信息，判断自己的想法究竟对不对。

创业者应该追求第二种。

甚至有时候，访谈最有价值的结果，是发现自己原本的创业想法根本不成立。

这不是失败，而是避免了后续更大的时间和金钱损失。

# 四、用户访谈最终应该产生什么成果？

这是我特别希望你理解的部分。

一次用户访谈结束后，不应该只是得到一份录音、一份文字稿和一份总结。

它应该帮助你产生至少四种成果：

| 成果     | 具体表现               |
| -------- | ---------------------- |
| 客户认知 | 更清楚谁是目标客户     |
| 问题认知 | 更清楚客户真正的痛点   |
| 商业认知 | 更清楚问题是否值得解决 |
| 行动决策 | 更清楚下一步应该做什么 |

举个例子。

假设你访谈了10家企业，发现：

- 其中8家使用 Excel 管理客户。

- 其中5家曾经发生过客户资料丢失。

- 其中3家为解决问题购买过 CRM。

- 其中2家最终放弃了 CRM，因为实施和维护成本过高。

这时你可能发现：

真正值得探索的机会不一定是「开发一款新的 CRM」。

而可能是：

为没有专业 IT 团队的小企业，提供低实施成本、易于使用的客户资料管理方案。

这就是用户访谈的价值。

它可能让你发现一个比原始创业想法更准确的市场机会。

当然，10家企业的访谈并不能代表整个市场，也不能直接证明这个商业机会成立。它只是帮助你形成更有依据的下一步假设，后续还需要进一步验证。

# 五、把用户访谈放到整个创业流程中理解

最后，我想帮你建立一个更大的框架。

用户访谈并不是创业的最终目的，它只是创业过程中获取市场信息、验证假设和降低风险的一种工具。

## 从创业想法到商业验证

1. 提出创业假设

我认为某类客户存在某个问题。

2. 用户访谈

了解客户、问题、行为和现有解决方案。

3. 分析证据

判断关键假设是否得到支持，哪些仍然未知。

4. 做出决策

继续探索、调整方向、验证解决方案，或停止。

5. 进一步验证

通过原型、实际试用、付费测试和销售等方式获取更强证据。

持续学习、验证和调整

注意，用户访谈主要帮助我们理解问题和客户，并降低早期探索的不确定性。它不能单独证明产品一定有人购买，更不能保证商业成功。后续还需要通过真实使用、购买和留存等行为验证。

现在我们可以重新理解这本书了。

它不是单纯教你如何和客户聊天，而是在教你：

如何通过客户交流，获得足以指导创业决策的可靠信息。

所以，我希望你第二遍阅读时，脑海里始终保留一个问题：

> 我学会这一章的知识之后，能帮助我在创业过程中降低哪一种不确定性？又能帮助我做出什么更好的决策？

举几个例子：

- 第1章：帮助我避免通过错误提问获得错误信息。

- 第2章：帮助我识别客户提供的信息是否具有证据价值。

- 第3章：帮助我把有限的访谈时间用在最重要的问题上。

- 第5章：帮助我判断客户是否愿意采取实际行动。

- 第7章：帮助我确定应该把精力放在哪一类客户身上。

这样，你就不会把第二遍阅读变成机械地收集知识点。

## 最后，我想给你留一个值得思考的问题

假设你访谈了20位潜在客户，最终发现：

- 15位都表示你的产品想法很好。

- 12位表示自己有这个问题。

- 8位表示愿意使用。

- 但没有任何一个人愿意投入时间、金钱或者其他实际资源来进一步尝试解决问题。

你认为这20次用户访谈算成功还是失败？为什么？

我希望你先用自己的理解回答。

这个问题可以检验你是否真正理解了：用户访谈的目标不是获得客户的认可，而是获得能够指导创业决策的证据。

Q：你提到是先“提出创业假设”，然后再去做“用户访谈”，也就是说用户访谈是为了验证创业假设是否成立，而不是为了创业者通过“用户访谈”来发现“创业点子”？

A：不是完全这样。你发现了一个很重要的逻辑问题，而且我需要修正一下之前给你的创业流程图。

用户访谈既可以帮助创业者发现创业机会，也可以帮助创业者验证已经形成的创业假设。它并不要求创业者必须先有一个完整的创业点子。

实际上，这两种用途对应创业探索的不同阶段。

我们先把一个容易混淆的概念区分开：

- 发现（Discovery）： 我不知道应该做什么，通过了解客户，发现值得解决的问题和创业机会。

- 验证（Validation）： 我已经有了某个假设，需要通过客户交流和其他实验，判断这个假设是否成立。

《妈妈测试》所教的方法，两种场景都适用。

## 一、两种创业场景，用户访谈的作用不同

### 场景A：还没有创业点子，通过访谈发现创业机会

假设你现在没有明确的创业想法，但对中小企业的经营管理感兴趣。

你可以主动寻找中小企业的老板、财务人员、销售人员进行交流。

你不需要先有一个产品想法，而是希望了解：

- 他们日常工作中有哪些麻烦？

- 哪些事情需要耗费大量时间？

- 哪些问题反复出现？

- 他们目前如何解决？

- 为了解决这些问题，他们投入过什么资源？

例如，你访谈了20位中小企业财务人员，逐渐发现：

- 很多企业的报销流程依赖人工。

- 财务人员需要花费大量时间核对票据。

- 已经有一些企业尝试购买自动化工具。

- 但现有工具的实施成本较高。

于是你发现了一个可能的创业机会：

「为中小企业提供低成本的自动化报销解决方案。」

这个过程就是：

创业机会发现

客户访谈 → 发现真实问题 → 识别需求模式 → 形成创业点子

这里需要强调：你不是让客户告诉你应该开发什么产品，而是通过了解客户的真实生活和工作，发现值得解决的问题，再由创业者自己设计解决方案。

### 场景B：已经有创业点子，通过访谈验证创业假设

假设你已经有了一个创业想法：

「我要开发一款帮助中小企业自动处理报销的 SaaS 产品。」

此时你已经有了一些假设：

1. 中小企业存在报销效率低的问题。

2. 这个问题足够严重，值得解决。

3. 现有解决方案不能很好地满足客户。

4. 客户愿意为更好的解决方案付费。

这时，你开展用户访谈，就是为了收集证据，判断这些假设是否成立。

创业假设验证

提出假设 → 客户访谈 → 收集证据 → 判断假设 → 调整创业方向

如果访谈发现：

- 客户确实存在报销问题；

- 但每个月只发生一次；

- 现有 Excel 已经足够解决；

- 客户没有意愿投入更多资源；

那么你的创业假设可能就不成立。

你应该调整方向，而不是继续开发。

## 二、其实还有一个更重要的区别：验证问题，不等于验证解决方案

我希望你把创业假设进一步拆成三个层次。

| 假设类型     | 需要回答的问题                             | 主要验证方式                       |
| ------------ | ------------------------------------------ | ---------------------------------- |
| 客户假设     | 谁会遇到这个问题？                         | 客户访谈、客户细分                 |
| 问题假设     | 这个问题真实存在且足够重要吗？             | 过去行为、问题成本、现有替代方案   |
| 解决方案假设 | 我的产品能解决问题，客户愿意使用和付费吗？ | 原型测试、试用、采购承诺、实际交易 |

这里有一个关键点：

用户访谈特别适合帮助我们理解客户、发现问题、验证问题假设。

但如果要证明客户真的愿意购买，最终还是要看客户是否愿意采取有成本的实际行动，甚至真正付费。

客户说问题存在，不等于问题值得解决；客户愿意解决问题，也不等于他愿意购买你的解决方案。

## 三、所以，真正完整的创业探索流程应该是这样的

我把之前的流程图重新修正一下：

## 创业机会发现与验证循环

第一步：选择探索方向

可以有创业点子，也可以只有感兴趣的客户群体或行业。

第二步：开展探索性用户访谈

了解客户的真实生活、工作、问题和过去行为。

第三步：发现问题并形成假设

明确目标客户、真实问题及其商业价值。

第四步：验证创业假设

通过访谈、原型、实验和客户承诺收集证据。

第五步：做出创业决策

继续推进、调整客户群体、改变解决方案，或者放弃。

新的信息会产生新的假设，再进入下一轮探索。

这个理解也符合《妈妈测试》的定位：作者教的是如何通过客户交流获得可靠信息，既帮助你了解真实需求，也帮助你判断商业想法是否值得继续。作者的官方网站也明确将其定位为帮助创业者学习客户真实需求、避免无效开发的实用指南。

The Mom Test+1

## 四、我希望你记住一个最重要的结论

用户访谈不是为了验证产品，而是为了帮助创业者理解市场和客户，减少创业决策中的不确定性。

有时候，它帮你验证一个创业点子。

有时候，它帮你发现一个从未想过的创业机会。

有时候，它帮你发现自己正在解决一个根本不值得解决的问题。

这三种结果都具有价值。

## 五、这也会影响我们接下来第二遍阅读的方式

我建议我们给《妈妈测试》增加一个贯穿全书的学习目标：

不只是学习如何做好用户访谈，还要理解如何利用客户访谈进行创业机会探索和创业假设验证。

以后每读完一章，我们除了讨论「如何访谈」，还要追问：

> 这一章的知识，究竟帮助创业者发现了什么？验证了什么？又帮助创业者做出了什么决策？

这样，你读完《妈妈测试》，得到的就不只是一套访谈技巧，而是一套以客户证据为基础的创业探索思维。
