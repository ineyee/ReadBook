#### 一、好问题都遵循三个规则

* 不要谈论你的点子，而是谈论客户的生活

* 不要询问客户对未来的想法，也不要询问客户过去的笼统情况，而是询问客户过去发生过的具体事件

* 少说，多听

#### 二、为什么“不要谈论你的点子，而是谈论客户的生活”

因为跟客户谈论你的点子时，客户很可能出于礼貌或善意给你类似“你这个想法很有前景”、“如果你做出来，我肯定买”这样的“假阳性”信号。而这类“假阳性”信号很容易让你对你的点子产生过于乐观的判断，比如你会误认为客户真得认为你的点子能解决他们的痛点、你会误认为客户真得愿意为你的点子付费。进而导致你投入大量时间和金钱，最终却做出一款压根没人买账的产品。总得来说，跟客户谈论你的点子很容易招来“假阳性”信号，而“假阳性”信号要比客户直接否定你的点子更加危险，因为它会让你在错误的方向上持续投入。

而谈论客户的生活，你才能发现客户到底在什么场景下遇到了什么问题，而不是你感觉他们可能存在什么问题，这起码能保证你的点子不是在解决一个你幻想出来的、压根儿不存在的问题。也许你的点子刚好能跟客户的问题相匹配，但不要高兴地太早，因为这只是初级证据，你仍然需要通过继续提问来验证客户的问题到底是不是真实痛点；也许你的点子本来就是幻想出来的、压根儿跟客户的问题不匹配，但不要气馁，因为你可以从客户真实存在的问题里发现自己原本没有意识到的却真正值得探索的点子，而不是局限于自己最初的点子。

记住，为了弄清客户是否在意你的点子，你反而应该决口不提它，而是谈论客户以及客户的生活。

#### 三、为什么“不要询问客户对未来的想法，也不要询问客户过去的笼统情况，而是询问客户过去发生过的具体事件”

首先说第一点“为什么不要询问客户对未来的想法”，因为“询问客户对未来的想法”，你容易获得的信息是客户七嘴八舌的愿望需求清单或者对未来的假设性承诺，这些信息都是客户的主观想法，它们都不应该作为验证点子或发现点子的证据，因为绝大多数客户可能知道自己遇到了什么困难，但不一定能够准确识别问题的根本原因，更不一定知道应该采用什么解决方案，也无法准确预测自己未来会采取什么行动。

然后说第二点“为什么不要询问客户过去的笼统情况”，因为“询问客户过去的笼统情况”，你容易获得的信息也是含含糊糊的，信息量不够，不足以指导你去判断客户的问题是什么、问题是否值得被解决、解决方案是什么。

最后说第三点“为什么要询问客户过去发生过的具体事件”，具体事件分三个层次，你可以通过“询问客户过去发生过的具体事件”获取到相应层次的证据来验证点子或发现点子，客户存在问题是初级证据 -> 问题存在，问题不解决对客户有很大影响是进阶证据 -> 候选痛点，客户已经有预算来解决这个问题是临门证据 -> 真实痛点。

记住，过去的事实比未来的想法更可靠，根据客户过去的事实去判断客户的问题是什么、问题是否值得被解决、解决方案是什么应该是你的责任，而不应该由客户告诉你。

#### 四、为什么访谈时应该“少说，多听”

你“多说，少听”就容易变成“跟客户谈论你的点子”，你“少说，多听”才容易变成“谈论客户的生活” + “客户有充足时间详细地口头描述或现场演示过去发生过的具体事件”。

记住，客户访谈的直接目的是向客户搜集信息，而不是向客户推销点子。

## 四层证据及其问题

第一、二、三层，主要是在收集客户信息、验证点子或发现点子。第四层，才开始把你的解决方案拿出来，测试客户是否愿意付费。

这也意味着，你不应该一开始就向客户介绍你的点子，而应该先通过前三层充分收集客户信息，等你确认问题存在、问题值得被解决，并且问题具有商业价值后，再进入第四层。

最终建议：以后每次做客户访谈，都按照这四层收集证据，但不要为了凑齐四层而强行提问。如果第一层就发现客户根本没有这个问题，就没有必要继续。如果第二层发现问题影响很小，也要谨慎。如果第三层没有任何资源投入，就需要进一步判断需求是否足够强。

并且要记住：**询问是为了搜集证据，而不是单纯把问题问出去，实际客户访谈中可能问题和答案都是层与层之间穿插着的，所以我们要练就的能力是“听到客户的回答后，能够识别自己已经获得了什么证据，以及下一步还需要收集什么证据”，而不是能背诵下来多少个访谈问题。**

| 问题                                                                                                                                                                                                         | 用途                                                                                                   |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------ |
| “你每天的工作生活中最重复且让你感到繁琐的任务是什么？”                                                                                                                                                       | **探索客户可能存在的问题**（如果你还没有明确的创业点子，可以问；如果你已经有明确的创业点子，可以不问） |
| “你近期的工作生活中有什么关注的目标，有没有遇到什么困难或限制条件？”                                                                                                                                         | **探索客户可能存在的问题**（如果你还没有明确的创业点子，可以问；如果你已经有明确的创业点子，可以不问） |

#### 获取第二层证据——【客户存在痛点——问题值得被解决】应该询问的问题

| 问题                                                                                                                                                                                                                                                                               | 用途                                                                                                                                                                                                                                                                                                                                                           |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| “你之前有没有寻找过解决办法来尝试解决这个问题？”<br/><br/>如果没有寻找过，继续询问“是不是觉得这个问题根本不在乎，连搜都懒得搜一下？”<br/><br/>如果寻找过，继续询问“之前你寻找的那些方案的主要问题在哪里？你是否正在寻找其它替代方案？如果是，卡在哪里？如果选择维持现状，为什么？“ | **验证问题是否严重到成为痛点——客户想主动解决**<br/><br/>如果客户之前从未寻找过解决办法，那就代表这个问题对他们来说不是那么严重，他们今后也不会来寻找更不会购买你的解决办法，没必要继续往下询问了<br/><br/>如果客户之前寻找过解决办法甚至目前仍在寻找解决办法，但是没找到满意的才选择了维持现状，可以视作他们目前的工具和流程就是那些不满意的，可以继续往下询问 |

| “如果解决这些问题，能产生多大价值？”                                                                                                                                                                                                                                               | **验证问题是否严重到成为痛点——问题解决可能给客户带来多大价值**<br/><br/>这也是定价的一点，常见的**定价原则是：根据产品为客户创造的价值来定价，而不是根据你的成本**                                                                                                                                                                                             |

#### 获取第三层证据——【客户存在强痛点——问题具有商业价值】应该询问的问题

| 问题                                                   | 用途                                                                                                                   |
| ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| “目前处理这个问题需要投入多少时间和人工？”             | **验证问题是否严重到成为强痛点——客户是否已经在投入时间和人力来解决这个问题**                                           |

| “之前有没有购买过类似的产品或服务来解决这个问题？”     | **验证问题是否严重到成为强痛点——客户是否曾经花过钱来解决这个问题**                                                     |
| “有没有采购更好解决方案的专门预算？”                   | **验证问题是否严重到成为强痛点——客户是否准备花钱来解决这个问题**                                                       |
| 如果有预算的话，询问客户“谁使用、谁付款、谁最终拍板？” | 我们必须弄清采购动的是谁的预算？公里还有谁有权让这笔交易泡汤？                                                         |
